# 💰 머니계산기

👉 https://머니계산기.kr

한국 생활에 필요한 금융 계산을 대출·부동산·금융 세 영역으로 나눠 제공하는 계산기 사이트입니다.
모든 계산기는 입력 즉시 계산되고, 입력값이 URL에 담겨 그대로 공유·복원됩니다.

---

## 계산기 구성

### 대출 (`/loan`)

대출이자 · 원리금상환 · 전세대출 · 중도상환 · DSR · LTV · 마이너스통장 · 대환대출 ·
금리변동 시뮬레이터 · 고정 vs 변동금리

> DSR은 소득 기준 한도, LTV는 담보 기준 한도입니다. 실제 한도는 두 값을 모두 충족해야 하며
> 금융회사 심사에 따라 더 낮아질 수 있습니다.

### 부동산 (`/real-estate`)

취득세 · 실투자금 · 월세 vs 전세 · 부동산 수익률 · 재건축 분담금 · 전월세 전환율 · 공실률 영향

> **부동산 자금 흐름**: LTV → 실투자금 → 수익률이 쿼리스트링으로 이어집니다.
> LTV → 실투자금은 주택가격·담보 기준 한도, 실투자금 → 수익률은 매입가·대출·보증금·부대비용을
> 넘깁니다. 금액 필드만 넘어가며, 사용자가 명시적으로 골라야 하는 항목(방공제·등기비용 등)은
> 인계하지 않습니다. DSR ↔ LTV는 요구 입력이 겹치지 않아 링크만 두고 값은 넘기지 않습니다.

### 금융 (`/finance`)

예금 이자 · 적금 이자 · 복리 · 목표 저축 · 예금 vs 적금 · CMA vs 예금 ·
실질금리 · 인플레이션 · 단리 vs 복리 · 환전

### 가이드 (`/blog`)

계산기와 짝을 이루는 해설 글. 분량이 아니라 각 절이 새 정보를 담는지를 기준으로 공개 여부를
관리하며, 비공개 글은 사이트와 사이트맵에서 함께 제외됩니다.

## 운영 원칙

이 사이트는 YMYL(금융) 영역이라 다음을 지킵니다.
적용은 **계산기**(엔진·UI·결과 문구·이용 안내)에서 확인했습니다.
`/blog` 가이드에 대한 적용 범위와 기존 글 표현의 정합성은 **후속 검토** 대상입니다.

**판정하지 않습니다.** 계산기는 숫자만 출력합니다. "유리하다", "갈아타는 게 좋다",
"이 정도면 안전하다" 같은 표현을 쓰지 않습니다. 전월세 전환율 계산기는 법정 상한 초과를
사실로만 표시하고 위법 여부를 판정하지 않으며, 대환대출 계산기는 두 관점을 나란히 보여줍니다.

**조용한 기본값을 두지 않습니다.** 근거 없는 수치가 결과에 몰래 들어가지 않도록,
사용자가 골라야 하는 항목은 선택 전까지 계산을 차단합니다. LTV의 방공제, 실투자금의
등기·법무 비용, 환전의 수수료율이 이 방식입니다.

**정책값은 계산 엔진과 분리합니다.** 세율·요율·한도 같은 규제 수치는 `src/lib/policy/`에
기준일·출처·지원 범위와 함께 두고, 계산 함수는 조회만 합니다. 정책 테이블에 없는 조건 조합은
임의로 보간하지 않고 "지원하지 않음"을 반환합니다.

**기준일을 화면에 표시합니다.** 현재 적용 상태는 계산기마다 다릅니다. LTV·실투자금은 `PolicyNote`
로 기준일·출처·제외 범위를 결과 하단에 노출합니다. DSR·전월세 전환율·취득세는 기준일을 문구로만
표시하고 출처는 함께 적지 않으며, 환전은 별도 표기가 없습니다. **정책 기반 계산기 전체를
`PolicyNote` 로 통일하는 것은 운영 목표이고 아직 구현되지 않았습니다.**

## 기술 스택

| 항목 | 값 |
|---|---|
| 프레임워크 | Next.js 16 (App Router) / React 19 |
| 언어·스타일 | TypeScript 5 / TailwindCSS 3.4 |
| 테스트 | Vitest (`src/lib/` 순수 함수 대상) |
| 배포 | 전 페이지 정적 생성 |

```bash
npm run dev           # 개발 서버
npm run build         # 정적 생성
npm run lint          # eslint
npm run type-check    # tsc --noEmit
npm test              # vitest run
npm run policy:check  # 정책 메타 구조·노후화 점검
```

### 계산기 한 개의 구조

```
src/app/<route>/page.tsx              서버 컴포넌트 (메타데이터·예시·FAQ·가이드)
src/components/calculator/XxxCalc.tsx "use client" (입력·결과)
src/lib/<domain>.ts                   순수 계산 함수
src/lib/policy/<name>.ts              정책값 (해당하는 경우)
```

`CalcShell`이 브레드크럼·계산 예시·이용 안내·FAQ 아코디언·관련 링크와
`WebApplication`/`BreadcrumbList`/`FAQPage` JSON-LD를 한 번에 처리합니다.
신규 계산기에서 이 껍데기를 다시 만들지 않습니다.

> ⚠️ `useCalcState`의 `getWon`/`getNum`은 한 렌더 늦은 값을 읽습니다(`@deprecated`).
> `useMemo` 안에서는 `readNum`/`readWon`을 쓰고, 0 판정은 truthy 대신 `isFilled`로 합니다.

저장소 문서는 `docs/` 아래에 모읍니다. **아래가 전부입니다.**

| 문서 | 내용 |
|---|---|

| `docs/BLOG-REVIEW-2026-08.md` | 블로그 통독 기록 |
| `docs/policies/*.md` | 정책 원문 조사 기록 (LTV·DSR·취득세·중개보수·환전) |

**현재 저장소에 없는 것** — 다른 프로젝트와 혼동하기 쉬워 적어 둡니다.

- `DECISIONS.md` (ADR) — 현재 없습니다. 설계 결정은 `docs/CALCULATOR-EXPANSION.md` 안에
  PR별 항목(D1~D4 = LTV, E1~E4 = 실투자금)으로만 기록되어 있습니다.
- `CHANGELOG.md` — 현재 없습니다. 변경 이력은 `git log`가 담당합니다.
- `notes/` — 현재 없습니다.
- `PLAN.md`(블로그 정예화 원본, 2026-05-02) — 저장소가 아니라 claude.ai 프로젝트에 있습니다.

> 확인 범위: 2026-09-16, 로컬 저장소의 `git log --all`(로컬 `refs/heads` + 마지막 fetch 시점의
> `refs/remotes/origin`)로 확인 가능한 이력 기준. 위 경로의 추가·삭제 이력은 확인되지 않았습니다.
> 아직 fetch되지 않은 원격 전용 브랜치와 별도·이전 저장소는 확인하지 않았습니다.

### 커밋 규칙

`타입(스코프): 한글 설명` 형식이며, 계산기 1개 = 커밋 1개가 관례입니다.
관심사별로 커밋을 나눠 되돌리기 쉽게 둡니다.

```
feat(loan): LTV 계산기 추가
fix(calc): 금융 4개 계산기 반응성 수정
docs(blog): 공개 글 최종 검토일 기록
```

## ⚠️ 안내

계산 결과는 참고용 예상치입니다. 실제 금융상품 조건·금리·세율·수수료와 금융회사 심사 결과에
따라 달라질 수 있으며, 법률·세무·금융 판단을 대신하지 않습니다.
정확한 내용은 금융기관 및 관련 기관의 공식 안내를 확인하시기 바랍니다.
