## 검증 증거와 범위

- 정적 분석, 타입 검사, 전체 회귀 검사, 프로덕션 빌드 통과.
- `npm run build`가 `scripts/check-site-urls.mjs`를 실행한다. 사이트맵 46페이지와 사이트맵 밖 색인 허용 페이지까지 총 46페이지의 canonical·og:url 경로, 자사 origin, OG/Twitter 절대 이미지 주소, 큰 카드, JSON-LD, robots, 실제 이미지 파일 존재를 검사한다.
- 생성 HTML과 대표 상태의 렌더 텍스트에서 camelCase/snake_case 식별자를 검사한다. 소스 AST에서 동적 조사 하드코딩을 검사한다. 프레임워크 내부 오류 문서와 noindex 경로는 색인 대상 검사에서 제외한다.
- 로컬 서버의 사이트맵 대상 46페이지·robots·사이트맵 응답을 확인했다. 대표 공유 이미지는 HTTP 200, image/png, 1200×630이었다.
- 입력·화면 회귀 범위: 보유·대출 금액 빈칸/0, 입력 삭제 시 결과 제거, 비활성 금리 오류, 선택 상태, 전체 계산기 초기 문구 및 주소 검사.
- 기존 공식 자료/수기 기대값 검사는 재실행했지만, 이번 작업에서 법령·금융 정책을 새로 확정하거나 모든 상품 조건을 검수하지는 않았다. 테스트 수·커버리지 비율을 정확성 근거로 사용하지 않는다.

## 주소 기준 1–4 재점검

- 하드코딩한 ASCII 정본은 한글 표시 주소를 `new URL()`로 변환한 결과와 빌드에서 대조한다.
- 호스트 비교·리다이렉트는 URL 파서가 정규화한 ASCII 값을 사용한다. 상대 경로 내부 링크는 유지한다.
- 현재 자사 슬러그는 ASCII다. 한글 호스트와 한글 경로를 함께 넣은 회귀 사례에서 호스트는 Punycode, 경로는 UTF-8 퍼센트 인코딩으로 처리되며 중복 인코딩되지 않는지 검사했다.
- 한글 표시 주소를 자사 호스트 비교나 메타 주소 생성에 직접 사용하는 경로는 없다. 공백에 조사 헬퍼를 적용하는 잘못된 변환도 빌드에서 차단한다.
- 이 재점검은 로컬 코드·생성물 확인이다. 푸시·운영 배포·수정 후 운영 확인은 미실시다.
- 재점검 검증: 주소·문구 회귀 검사, 정적 분석, 타입 검사 통과. 앞서 생성한 빌드 산출물에 최신 주소·문구 검사를 다시 실행해 통과.
