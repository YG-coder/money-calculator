## 1. 확정된 값과 근거 등급

### 1.1 신용대출 스트레스 DSR 구조

```text
신용대출 총잔액(기존 + 신규) ≤ 1억원
  → 스트레스 금리 미적용

신용대출 총잔액(기존 + 신규) > 1억원
  → 스트레스 금리 × 금리유형별 적용비율
       만기 5년 이상 고정금리 ......  0%   (미적용)
       만기 3년 이상 5년 미만 고정 ..  60%
       그 밖의 대출 ................ 100%
```

| 항목 | 등급 | 근거 |
|---|---|---|
| 1억원 게이팅 | **1차** | 금융위 「스트레스 DSR 제도 시행」 2023-12-27 |
| 5년 이상 고정 0% | **1차** | 동 자료 |
| 3~5년 고정 60% | **1차** | 동 자료 |
| 그 밖 100% | **1차** | 동 자료 |
| **2026년 현재도 동일 유지** | **1차** | **금융위원회공고 제2026-362호** 「스트레스 DSR 3단계 행정지도 변경시행 예고」 (공고일 2026-06-18) |

값 자체의 근거(2023 도입 자료)와 "지금도 그 값이냐"의 근거(2026 공고)는
서로 다른 문서입니다. 값을 수정할 때는 **두 문서를 모두** 다시 봐야 합니다.

### 1.2 ⚠️ 구현 시 혼동 주의 — 두 개의 금리유형별 표

**신용대출 표**와 **주택담보대출 표**는 다릅니다. 섞으면 안 됩니다.

| | 신용대출 | 주택담보대출 |
|---|---|---|
| 기준 축 | **고정금리 기간** (5년↑ / 3~5년 / 그 밖) | 상품유형 (변동 / 혼합형 / 주기형) |
| 게이팅 | 잔액 1억원 초과 시에만 | 없음 (항상 적용) |
| 지역 차등 | **없음 (전국 동일)** | **있음 (수도권·규제 / 지방)** |

rev.1 에서 "주담대 혼합형 60% 가 혼입된 것 같다"고 의심했던 부분이 여기입니다.
두 표가 구조적으로 닮았을 뿐, **신용대출 60% 는 신용대출 표의 고유값**입니다.

코드에서는 두 테이블을 **다른 이름의 별도 상수**로 두고,
한쪽 함수가 다른 쪽 테이블을 참조할 수 없게 타입을 분리합니다.

### 1.3 그 밖의 유효 값

- DSR 한도: 은행권 **40%**, 비은행권 **50%** — 변경 근거 없음
- 지방 주담대 스트레스 유예: **2026-12-31** — 공고 제2026-362호에서 확인

## 2. 스트레스 금리는 상수가 아니라 반기 산정값

이 절이 이번 재검증에서 코드 구조에 가장 큰 영향을 줍니다.

### 2.1 산정 구조

```text
일반 스트레스 금리
  = 과거 5년 中 최고 가계대출 금리 − 현재 금리(5월 · 11월 기준)
  단, 일반 대출은 하한 1.5%p · 상한 3.0%p

발표: 연 2회 (6월 · 12월)
적용: 발표 이후 6개월
  2026-H2 = 2026-07-01 ~ 2026-12-31  ← 현재 구간
```

현재 산정 결과는 **하한에 걸려 1.5%** 입니다.
즉 `1.5` 는 영구 상수가 아니라 **"지금 반기의 산정 결과"** 입니다.

### 2.2 세 값의 관계

| 대상 | 적용 스트레스 금리 | 산출 |
|---|---|---|
| 신용대출·기타대출 | **1.5%** | 일반 스트레스 금리 그대로 (전국 동일) |
| 수도권·규제지역 주담대 | **3.0%** | 10·15 대책 이후 **별도 강화 하한 3.0%** |
| 지방 비규제 주담대 | **0.75%** | 일반 1.5% **× 2단계 적용비율 50%** |

여기서 세 값 모두를 각각 독립 상수로 박아두면,
**다음 반기(2026년 12월 발표)에 일반 스트레스 금리가 1.5% 에서 움직일 때
신용대출과 지방 주담대만 조용히 틀린 값이 됩니다.**

전월세 전환율에서 `getLegalConversionCapPct()` 로 단일 출처화한 것과 같은 문제입니다.

### 2.3 권장 데이터 구조

```ts
export const STRESS_RATE = {
  currentPct: 1.5,        // 2026-H2 산정 결과 (= 하한에 걸린 상태)
  minPct: 1.5,            // 일반대출 하한
  maxPct: 3.0,            // 일반대출 상한
  applicableHalf: "2026-H2",
  effectiveFrom: "2026-07-01",
  effectiveUntil: "2026-12-31",
} as const;

// 수도권·규제지역 주담대: 별도 강화 하한
export const METRO_MORTGAGE_MINIMUM_PCT = 3.0;

// 지방 비규제 주담대: 2단계 적용비율 (유예)
export const LOCAL_MORTGAGE_PHASE_RATIO = 0.5;
export const LOCAL_MORTGAGE_DEFERRAL_UNTIL = "2026-12-31";
```

파생 함수:

```ts
// 신용대출·기타대출 — 전국 동일
export function getCreditStressRatePct(): number {
  return STRESS_RATE.currentPct;
}

// 지방 비규제 주담대 — 일반 스트레스 금리에서 파생
export function getLocalMortgageStressPct(): number {
  return STRESS_RATE.currentPct * LOCAL_MORTGAGE_PHASE_RATIO;
}
```

### 2.4 ⚠️ 수도권 3.0% — 해석이 갈리는 지점

"강화 **하한** 3.0%" 이므로 문언대로면 `max(현재 스트레스 금리, 3.0)` 입니다.
그런데 현재 스트레스 금리가 1.5% 이므로,
**"하한 해석"과 "고정값 3.0 해석"이 지금은 같은 값을 냅니다.**

두 해석이 갈리는 것은 일반 스트레스 금리가 3.0% 를 넘을 때뿐이고,
일반대출 상한이 3.0% 이므로 그 경우에도 초과하지 않습니다.

→ **현재 값은 어느 해석으로도 3.0 으로 동일**하므로 구현에 지장은 없습니다.
   다만 `max()` 로 적어두고 주석에 이 사실을 남깁니다. 값 대신 관계를 기록하는 편이 안전합니다.

```text
  금리유형별 적용비율        : 변경 없음
  차주별 DSR 한도 40/50      : 변경 없음
  청년 장래소득 적용 안내 절차 : 개선 (금융회사 안내 의무)
  전세대출 취급 제한 등 수요관리 : 별도 조치 있음(산식 변경 아님)
```

"변경 없음"은 **8·13 공식 발표 및 별첨 자료에 해당 수치 변경 기재가 없다**는
범위에서의 결론입니다. 부존재 증명이 아닙니다.

가계대출 총량 목표는 금융회사 대상 총량 규제로, **개별 차주의 DSR 계산식에는 들어가지 않습니다.**
계산기에 반영할 항목이 아닙니다.

## 4. 지방 주담대 0.75% 유예

```text
일반 스트레스 금리 1.5%
  × 2단계 적용비율 50%
  = 0.75%

대상 : 수도권·규제지역 밖의 주택담보대출
기한 : 2026-12-31
```

- **신용대출에는 이 지역 유예를 적용하지 않습니다.** (신용대출은 전국 1.5%)
- 8·13 대책의 조기 종료·연장 언급은 확인되지 않았습니다.
- 이미 두 차례 연장된 이력이 있어 **재연장 가능성이 있습니다.**
  → 2026년 12월 운영방향 발표 시 재확인. 만료일을 지나면 값이 자동으로 틀려지므로
     코드에 만료 처리(또는 경고)를 둡니다.

## 5. 스트레스 DSR 4단계

2026-08-25 현재 **확정 시행일도 확정 수치도 확인되지 않습니다.**

그 위에 10·15 대책의 수도권·규제지역 3.0% 강화와 지방 유예가 얹혀 있는 상태입니다.


## 6. 신용대출 원리금 산정 — 부분 확인

v2 주석의 **"약정만기·상환방식 무관 일괄 5년 원금균등"** 은 부정확합니다.

| 유형 | 산정만기 | 등급 |
|---|---|---|
| 일시상환 신용대출 | 5년 | 확인 |
| 마이너스통장 | 5년 (약정한도 전액 기준) | 2차 — 감독업무시행세칙 원문 미대조 |
| **적격 분할상환 신용대출** | **실제 만기, 최장 10년** | 2차 (방향 확인, 요건 미확인) |

모든 신용대출을 `원금 ÷ 5 + 이자` 로 계산하면
**장기 분할상환 대출의 DSR 을 과대 표시**합니다.

인정 요건과 원금 산식은 현행 **은행업감독업무시행세칙 별표 원문**에서
직접 확인하지 못했습니다. → 확정값으로 구현하지 않습니다.

**PR 3 처리 방침**

- 일시상환·마이너스통장 → 산정만기 5년 적용
- 분할상환 신용대출 → **사용자가 실제 연간 원리금을 직접 입력** (또는 `unsupported`)
- **"모든 신용대출은 5년"이라는 문구를 UI·주석 어디에도 쓰지 않습니다.**

## 7. 전세자금대출 — 조건부

v2 주석의 **"전세대출은 이자만 반영"** 이라는 단일 규칙은 틀립니다.

```text
1. 무주택자 전세대출
     → DSR 산정 제외

2. 1주택자가 수도권·규제지역에서 임차인으로 받는 전세대출
     → 이자상환분만 DSR 반영

3. 기존 전세대출의 단순 만기연장
     → 원칙적으로 신규 적용 제외

4. 만기연장 시 증액
     → 증액분을 신규대출로 보아 적용

5. 그 밖의 조건 (지방 등)
     → 자동 판정하지 않음 / 금융회사 확인 안내
```

근거: 2025-10-29 시행 대책 (10·15 대책 원문).

**UI 요구사항** — 조용한 0원 금지 원칙에 따라, 전세대출 입력은 3-state 명시 선택입니다.

```text
전세대출이 있으신가요?
  ○ 없음
  ○ 무주택자로 받은 전세대출        → DSR 제외 (0원, 근거 표시)
  ○ 1주택 + 수도권·규제지역 임차     → 이자만 반영 (이자액 입력)
  ○ 그 밖의 경우                    → 자동 판정하지 않음, 금융회사 확인 안내
  (미선택 시 결과 대신 안내 문구)
```

`○ 없음` 과 `○ 무주택자` 는 둘 다 결과가 0원이지만 **이유가 다르므로 화면에 구분 표시**합니다.
(취득세 저가주택 주택 수 산정에서 같은 문제를 겪은 전례가 있습니다.)

## 8. PR 3 v2 구현 범위 — 착수 가능

### 8.1 지금 구현하는 것

```text
[신용대출]
  · 총잔액 1억원 초과 게이팅
  · 금리유형별 적용비율   5년↑ 고정 0% / 3~5년 고정 60% / 그 밖 100%
  · 지역 구분 없음 (전국 일반 스트레스 금리 1.5%)
  · 일시상환 산정만기 5년
  · 마이너스통장: 약정한도 전액 기준, 산정만기 5년

[주택담보대출 — 기존 v1 유지 + 구조 개편]
  · 수도권·규제지역 3.0%  (max(현재 스트레스 금리, 3.0) 으로 기록)
  · 지방 비규제 0.75%     (현재 스트레스 금리 × 50%, ~2026-12-31)

[전세자금대출]
  · 무주택 제외 / 1주택+수도권·규제 이자만 / 그 밖 안내

[공통]
  · DSR 한도 은행 40% · 비은행 50%
  · 스트레스 금리 반기 구조 (currentPct / min / max / applicableHalf)
  · 1억원 상수 2개 분리 (DSR 적용 기준 vs 신용대출 스트레스 게이팅)
```

### 8.2 상수 분리 — 두 개의 1억원

```ts
// 차주단위 DSR 적용 기준 — 총 대출 기준
export const DSR_APPLICATION_THRESHOLD_WON = 100_000_000;

// 신용대출 스트레스 게이팅 — 신용대출 총잔액 기준
export const CREDIT_STRESS_GATE_WON = 100_000_000;
```

값이 같다고 한 상수로 합치면, 한쪽만 바뀔 때 다른 쪽이 조용히 따라 움직입니다.

### 8.3 `Region` 격리

현재 `getEffectiveStressRate({ region, rateType })` 는 주담대 전용입니다.
v2 에서 신용대출 경로가 생기면 **`Region` 이 신용대출 계산에 흘러들어갈 수 있습니다.**

→ 함수를 분리하고, 신용대출 함수는 `Region` 을 **인자로 받지 않습니다.**

```ts
getMortgageStressRatePct({ region, rateType }): number   // 주담대 전용
getCreditStressRatePct({ fixedTerm }): number            // 지역 인자 없음
```

타입 수준에서 막지 않으면 회귀 테스트로만 잡아야 합니다.

## 9. 구현하지 않는 것 — `unsupported`

1. 분할상환 신용대출의 실제만기 인정 **요건**과 세부 원금 산식
2. 마이너스통장 산정만기의 **1차 원문**(감독업무시행세칙 별표) 대조
3. 기타대출 종류별 세부 산정만기
4. 보증기관(HF / HUG / SGI)별 전세대출 DSR 취급 차이
5. 스트레스 DSR **4단계**
6. 지방 주담대 유예의 2026-12-31 **이후** 처리
7. 주택담보대출의 혼합형·주기형 적용비율 (v1 부터 미지원, 범위 유지)

각 항목은 결과 화면에서 **"이 조건은 자동 계산하지 않습니다 — 금융회사 확인"** 으로 안내합니다.
값을 추정해 넣지 않습니다.

```text

[입력 게이트]

13. 전세대출 '없음' vs '무주택 제외'      → 둘 다 0원, 표시 문구는 다름

[한도]
14. 은행 40% / 비은행 50% 경계값
```

```text
  1억원 상수 2개 분리 (DSR 적용 기준 vs 신용대출 게이팅)
  추정 가능액의 1억원 경계 분기
```

### 14.3 구현하지 않고 차단한 것

| 조건 | 화면 동작 |
|---|---|
| 전세대출 미선택 | 결과 대신 선택 요청 |
| 전세대출 '그 밖' | 자동 판정하지 않음 안내 |
| 분할상환 신용대출 (직접 입력 전) | 실제만기 미확인 사유 + 직접 입력 요청 |
| 지방 주담대 유예 만료 후 | 유예 종료 사유 + 금융회사 확인 안내 |

9절의 나머지 항목(4단계, 보증기관별 차이, 기타대출 산정만기)은 고지 문구로 노출합니다.

### 14.4 적격 분할상환 잔액 — 별도 필드로 분리한 이유

분할상환 신용대출은 연간 원리금을 자동 계산하지 않고 사용자가 '기타 부채'에 입력합니다.
그런데 그러면 **잔액이 게이팅 판정에서 사라집니다.**

실측 (분할상환 8,000만원 보유 + 신규 일시상환 5,000만원, 연소득 1억):

```text
잔액 미입력 : 총잔액  5,000만원  게이팅 false  스트레스 0     DSR 30.5%
잔액 입력   : 총잔액 13,000만원  게이팅 true   스트레스 1.5   DSR 33.2%
```

DSR 이 2.7%p **낮게** 나오므로 한도를 과대 표시하는 방향입니다.
그래서 `creditInstallmentBalance` 를 별도 필드로 두고

- 게이팅(`existingCreditTotal`)에만 합산
- 연간 원리금 자동 계산에서는 제외
- 추정 가능액의 1억원 경계에도 포함
- URL 상태에 포함

중복 경고는 조건을 갈랐습니다. `기타 부채 + 일시상환/마이너스통장`은 중복 위험이므로 경고하고,
`기타 부채 + 적격 분할상환 잔액`은 **의도된 정상 조합이므로 경고하지 않습니다.**
대신 신규 대출이 신용대출인데 잔액 칸이 비어 있으면 조건부 안내를 띄웁니다.
